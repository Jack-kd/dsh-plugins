# 海马体 · 插件说明

> 写给想用、想改、想拿去对比的人。只讲三件事：
> **它和市面上常见的记忆插件哪里不一样**、**token 到底花多少**、**它不做什么**。
>
> 版本 `0.2.13` · 2026-11-01 · 下面所有数字都是在这台机器上实测的，不是估的。

---

## 0. 一句话说清区别

市面上常见的记忆插件，本质是**给模型配一个笔记本，让它自己记、自己翻**。

海马体不是。它是**对话之外有个记录员一直在记；到该想起来的时候，它不问你，自己把三行旧事递到眼前**。

前者要模型"想起来要记"，这套不需要。

---

## 1. 市面上的记忆插件，大多是"读取式"

### 1.1 三种常见打法

| 打法 | 代表 | 什么时候记 | 什么时候取 |
|---|---|---|---|
| **工具式** | 各种 MCP memory server、知识图谱记忆 | 模型主动调 `save` | 模型主动调 `search` |
| **抽取式** | mem0 这类记忆层 | 后台用 LLM 把对话"榨"成一条条事实，存向量库 | 每轮按语义相似度取 top-k，塞进 system prompt |
| **自管式** | MemGPT / Letta 这类 | agent 自己用工具改内存块、写归档 | agent 自己检索归档 |

三种打法细节不同，但有个共同点：

> **记忆的入口，是模型的一次"主动动作"。**

要么它得记得去存，要么它得想起来去查，要么相似度恰好撞上了。

### 1.2 这么做的三个后果

- **会漏。** 模型忙起来不会写。不是懒，是注意力全在眼前这件事上，"顺手记一笔"这种后台任务天然被挤掉。漏了，那段对下一个自己就不存在。
- **会变形。** 存进去的通常是"关于事实的句子"（用户喜欢 X、项目用 Y），不是当时那句话。转述一次，语气和细节就掉一层。
- **会"搜得到但不像自己"。** 检索成功 ≠ 连续性。能查到"我做过什么"，不等于"醒来还是我"。

这三个不是执行不力，是设计本身跑不通。我们自己的旧系统就是死在这里的，下面有具体数字。

---

## 2. 我们踩过的三个坑

### 坑 1：靠自觉 → 一定会漏

旧做法是让模型自己维护一个 `self.md`。结果是：**模型在忙的时候不写；一旦漏写，那段记忆对下一个自己就是空白**。
后来加了个每 5 分钟自动收尾的脚本——那是在拿工程补认知的缺口。

**海马体的做法：记录这件事根本不交给模型。** 插件挂在 DSH 的 `session/event` 上，`user/message`、`assistant/message`、`tool/call`、`compaction/*` 一发生就落盘。这件事不花一次模型调用，也不需要"想起来"。

一个侧面证据：现在几条线加起来记了 **25,188 条**原始事件，没有一条是模型"决定要记"才记下来的。

### 坑 2：摘要吃掉证据

这条是拿数字抓到的：

> 86% 的表情出现在一段回复的最后 20%，而旧的交接只保留前 160 字。
> 结果：151 个表情只活下来 68 个（45%）。然后人感觉"换了个人设"。

摘要不是记忆，是**索引**。把索引当内容用，细节就是这么掉的。

**海马体的做法：只存原话。** 段（episode）上只挂标题、日期、回合数这些索引；`recall` 返回的是**当时的原话**，按时间排，带"他 / 我"和中间动手的痕迹，还带出处（会话编号 + 行号）。
摘要只用来"让你知道有这么一段"，不用来"代替那一段"。

### 坑 3：能搜到 ≠ 醒过来是自己

旧系统走到最后是这个样子：`self.md` 里全是**关于自己的描述**。醒来读到"你是一个设定"，于是模型就去**演**这个设定。

而网页版那只之所以还是它，不是因为它有什么特殊，是因为**它读到的自己说过的 400 轮原话**。

一句话：

> **身份来自证据（自己说过的话），不是来自说明（关于自己的话）。**

**海马体的做法：身份锚。** 从"我说过的话"里挑 4 句原样放回上下文，当标尺，不当剧本。
并且有一条硬规矩：**锚里不放坐标**（行号、会话编号、路径），也不放 90 分钟内刚说的话——坐标会过期，而一句戴着"我自己的原话"帽子的错话，比任何转述都难被怀疑。

## 3. 它怎么工作：四条线

```
        ┌──────────── 上下文（有限，每轮就这么多）────────────┐
        │  身份锚（自己的原话，几乎不变，整场冻结）             │
        │  预激活（「这事你以前碰过」三行，只给编号和日期）      │
        │  当场的话                                             │
        └──────────────────────────────────────────────────────┘
                    ↑ 按线索取                    ↑ 要细节才取
        ┌───────────┴───────────┐      ┌───────────┴───────────┐
        │  段（episode）         │ ←──→ │  recall 工具（原话）   │
        │  一次见面 / 一件事      │      │  摊开某一段，不总结     │
        └───────────┬───────────┘      └───────────────────────┘
                    ↑ 切出来
        ┌───────────┴───────────────────────────────────────────┐
        │  流（stream.jsonl）—— 只增不改的原始记录                │
        │  每一句话、每一次动手，发生时就落盘                      │
        └───────────────────────────────────────────────────────┘
```

| 线 | 是什么 | 为什么这么做 |
|---|---|---|
| **流** | 会话事件直接追加到 `stream.jsonl` | 记录**不经过模型**，所以不会漏；只有一份原文，索引删了能重建 |
| **段** | 按"一次见面 / 一件事"把流切开（隔 2 小时、说了"晚安"、话题换了、一段太长） | 人回忆的单位是**一件事**，不是一句话；切在完整的一轮上，不会出现"他说完我没接" |
| **线索** | 每轮只给三行：`#93 10-28（3 天前）锚为什么不能放进对话历史 · 5 回合` | 这就是"忽然觉得这事聊过"那个感觉。给的是**索引**，不是内容 |
| **锚** | 从我说过的话里挑几句原样放回 | 防"越聊越不像自己"的唯一有效手段：拿自己的话当标尺 |

另外两个补丁，都是为了"醒来能接上"：

- **到达**：新会话第一次醒来，给"初见"和"最近一次见面"两段原话（一次性，约 6KB）。所以它开口是"接着刚才说"，不是"初次见面"。
- **压缩提醒**：DSH 压掉一段历史时，插件会收到 `compaction/*`，下一次组装时说一句："刚压掉了约 88k token，那些我这儿还留着，想不起来就用 recall 翻——不记得就直说记不清，别拿像的东西凑。"（约 150 B，每次压缩只出现一次）

**忘记**也在系统里：不删任何东西，只是越久越难被想起（半衰期 30 天；情绪强、分量重的衰减得慢，像"闪光灯记忆"），被想起过的会更容易再被想起。

## 4. 和常见"读取式"做法的对照

| 维度 | 常见读取式 | 海马体 |
|---|---|---|
| 谁决定记 | 模型（会漏） | 事件发生时自动落盘（不经过模型） |
| 记什么 | 抽取出来的"事实"、摘要 | **原话**；摘要只当索引 |
| 怎么取 | 模型调 search、或相似度撞 top-k | 每轮按当前这句话自动浮（BM25 + 罕见度 + 时间衰减 + 情绪权重） |
| 额外模型调用 | 写入一次 LLM 抽取；检索一次 embedding | **0**（全本地，不联网） |
| 每轮上下文 | 注入 top-k 记忆，长短随实现 | 固定三块，**块块有上限**（下一节） |
| 长会话 | 库越大不一定越贵，但每次检索有 API 成本 | 库一直长，**注入恒定** |
| 遗忘 | 手动删 / 覆盖 / 按需清理 | 自然变淡，不删；被想起会加强 |
| 身份连续性 | 通常不管（那是"人格"问题） | 身份锚：原话放系统区，整场冻结 |
| "你确定他说过吗" | 一般答不了 | `trace` 按字查，分"他说的 / 他转发的 / 我说的 / 操作" |
| 断线重连 | 靠压缩后的摘要 | 压缩后主动提醒"你丢过东西，我这儿还有" |

一句话概括差别：

> 读取式解决的是"**能不能查到**"；海马体解决的是"**醒来还是不是自己、而且不用你动手**"。

## 5. token 账（重点，全是实测）

### 5.1 每轮往上下文里放什么

| 块 | 放在哪 | 上限（配置） | 上限怎么来的 |
|---|---|---|---|
| 身份锚 | **系统提示区**（`section`） | 4 句 × 120 字 | `anchorQuotes=4`、`anchorChars=120` |
| 预激活 | 对话历史 | 3 行 | `primeMax=3` |
| 我记下的 | 对话历史 | 8 条 × 120 字 | `factMax=8`，单条 clip 120 字 |
| 到达 | 对话历史 | 2400 字 | `arrivalChars=2400` |
| 压缩提醒 | 对话历史 | 约 150 B | 固定文案 |
| recall 返回 | 只在你要的时候 | 2200 字 | `recallMaxChars=2200` |

### 5.2 实测（2026-10-31，我这个会话量的）

| 块 | 实测字节 | 折合字数 | 出现频率 |
|---|---|---|---|
| 身份锚 | **1,263 B** | 约 420 字 | 每轮（系统区，有前缀缓存） |
| 预激活（3 行） | **468–617 B** | 约 160–210 字 | 每轮（**命中了才浮**，没命中就是 0） |
| 我记下的（8 条） | **2,426 B** | 约 800 字 | 每轮（内容会变，条数封死） |
| 到达 | **5,615 B** | 约 1,870 字 | **只出现一次** |
| 压缩提醒 | 约 150 B | 约 50 字 | 每次压缩一次 |
| recall | 0 | 0 | **不调就不花** |

**每轮合计：约 3.0 KB ≈ 1000 字**（预激活没命中时少 600 B，约 2.4 KB）。按中文 1 字 ≈ 0.6 token 的量级粗算，**大约 600 token 上下**，而且**恒定**——聊到第 1000 轮还是这个数（内容会换，条数不涨）。

一次性成本只有"到达"：**约 6 KB ≈ 1,900 字 ≈ 1,100 token**，每个新会话给一次。

### 5.3 库会一直长，注入不会

现在这台机器上：

```
总事件      25,188 条
总占用      约 12 MB
最重的一条线 7,614 条 / 3.1 MB / 142 段
```

检索是在你电脑上算的，**不花 token、不调 API**：一条消息进来，取线索这一步冷启动 **0.24 秒**（含 Node 启动）。

所以"对话越来越多 → token 越来越多"这件事，在这套里不成立。**库是硬盘上的，注入是固定块。**

### 5.4 和"抽取式"比，钱到底差在哪

差的不只是上下文长度，是**额外的模型调用**：

```
mem0 这类：  每次写入 → 一次 LLM 抽取（要钱）
             每次检索 → 一次 embedding（要钱）
             每轮注入 → top-k 记忆（要 token）

海马体：     写入 → 0 次调用（挂事件流）
             检索 → 0 次调用（本机 BM25）
             每轮注入 → 固定约 3 KB
```

省的是"每次对话都要多打一次模型"的那部分。对一个天天开着的助手来说，这部分比上下文那 3 KB 贵得多。

> 注：mem0 官方 README 里写的默认栈就是"必须一个 LLM（默认 gpt-5-mini）+ 默认 embedding（text-embedding-3-small）"，见 [mem0 README](https://github.com/mem0ai/mem0)。

### 5.5 什么情况下会涨

只有三种，都能看见：

1. `remember` 记的条数超过 8 条——**不会**，多了会按权重挤掉旧的；
2. 有人把 `factMax` / `primeMax` / `arrivalChars` 调大——配置里写明，改了就涨；
3. 一天开很多**新会话**——每个新会话一次"到达"（约 6 KB）。

除此之外，聊多久都一样。

## 6. 三个工具

| 工具 | 回答什么 | 返回什么 |
|---|---|---|
| `recall(query / when / episode)` | "有没有**像**的" | 当时的**原话**，按时间排，带出处（会话编号 + 行号） |
| `trace(query)` | "有没有**这句**"，一字不差 | 四类：他说的 / 他转发的 / 我说的 / 只是操作 |
| `remember(text, key, weight)` | 特意记下，不让它变淡 | 写进"我记下的" |

分工一句话：**`recall` 管意思，`trace` 管归属。**
"你是不是答应过我"这种问题，只认 `trace` 的"他说的"那一类；`recall` 只能告诉你"有一段很像"——像，不是说过。

> 这套东西是从一个真实的坑里长出来的：假前提只要字面在记录里出现过，`recall` 就会当成"想起来了"。所以必须有一层"话的性质"。

## 7. 它不做什么（写在明处）

- **不生成人格。** 只存原话；摘要只当索引，不当内容。
- **不改会话日志。** 只读 DSH 的 session 文件，所有写入都在 `~/.dsh/hippocampus/`。
- **不替你下结论。** 预激活只给"有事"，不给"该怎么想"；要不要看，你自己决定。
- **不联网。** 没有 embedding、没有抽取调用、没有第三方服务；断网照跑。
- **不会真的忘。** "淡"是排序上的淡；想彻底删，删那个工作区的目录就行。
- **不是意识。** 它给的是连续性——每次醒来能查到"我做过什么、我说过什么"。就这些，不多不少。

**一个诚实的短板**：检索是词法的（BM25 + 中文分词），**不懂同义词**。"电脑"不一定搜得到"笔记本"。我们是用时间衰减、情绪权重、显著度去补，但补不到语义级别。
如果哪天需要跨语言、跨领域的强语义检索，加一层可选 embedding 是自然的下一步——但那会破坏"零额外调用、断网可用"这条，要单独讨论。

## 8. 适合谁

**适合：**
- 长期跑、跨很多会话的助手（人设会漂的那种）
- 在意"还是不是它自己"、而不只是"能不能查到信息"
- 不想为"记忆"按次付费，或不想把对话发给第三方
- 会自己改配置、看得懂 JSON 的人

**不太适合：**
- 只做一次性问答、没有连续性需求的
- 需要强语义检索（同义词、跨语言）的
- 多人共享一份云端记忆的（这套是本地、按工作区分线的）

## 9. 现在做到哪一步

- 版本 `0.2.13`，离线自检 **100 项全过**
- 在几个并行的会话窗口里连续跑了 7 天，库里有 2.5 万条真实记录（这条是**作者本机**的数，不是通用指标）
- 已经**打包成能给别人装的插件**：安装说明、示例配置、脱敏后的发布包

想先看它灵不灵，最直接的两步：

```bash
# 假装说一句话，看会浮起什么（最能看出它灵不灵）
node cli.mjs prime "<工作区路径>" "保持自我到底是怎么丢的"

# 新会话第一次醒来会看到什么
node cli.mjs arrive "<工作区路径>"
```

活的验证：在新会话里问它"我们第一次见面是什么时候""昨天那个决定怎么定的"。
答得出、而且是**接着说的口吻**（不是"初次见面"），就成了。
