# 变更记录

版本号只跟「装进去的东西变了」走，不跟日期走。
打包版本在 `package.json`，运行时会把它写进 `~/.dsh/hippocampus/diag.log` 的
`apply 跑完 · vX.Y.Z` 那一行——**别再出现「代码改了两轮、日志里还写着 v0.1」那种事**。

**发版三步（别省）**：
1. 在这一节加一条，标题写成 `## 0.2.3 · 2026-10-27 · 这一版修了什么`——第三段直接进桌面版本表；
2. 改 `package.json` 的 `version`；
3. 跑 `node 工具/冻结插件.mjs`（它会冻结整包，并顺手刷新桌面 `海马体-版本表.md`）。

版本表是**算出来的**（从这里抽），所以：只改表不更这一节，表会说谎；
只更这一节不跑冻结，表里就没有这一行。

## 0.2.13.10 · 2026-11-01 · 「也提过」必须比第一行更新（内部实测补）

**0.2.13.9 装完当场炸的 bug**（另一位维护者实测两处）：

```
衰减      → 11-01 09:24（第一行已经是最新的）
           另：10-31 20:31（段 #160）也提过——最近一次是那段   ← 更早，话说反了
```

原因：`recentMention` 只排除了「第一行那段自己」和「当前会话」，**没要求候选比第一行更新**。
于是第一行就是最新那段时，它往回挑一段更早的，还照样说「最近一次是那段」。

**改一行**：候选必须 `endTs > target.endTs`。

**自测补两条**（都直调 `recentMention`，不受排序影响）：

- 第一行已是最新那段 → 返回 `null`（不往回挑）
- 第一行较旧 → 指向更新的那段

自测 **100 过**，冒烟 **59 过**。

## 0.2.13.9 · 2026-11-01 · 回忆头部补一句「最近也提过」（内部实测补）

**起因**：问「海马体 衰减」，它给 10-31 那段。那段一分半钟里说了 28 次，按「哪段最像在说这件事」
排第一没毛病；但人会以为「今天没聊过」。这是**口径差，不是排序错**。

**改法**：`recallBlock` 头部多一行，**排序一个字没动**。

```
【想起来了 · 2026-10-30 10:05　…】
出处：会话 old · 第 1–10 行（这段 10 句对话、0 次动手）
另：2026-11-01 08:05–08:05（段 #1）也提过——最近一次是那段，不是这里。
```

**三条自律**（都进了自测）：

1. **只在真要提时出现**：近 24h 内有另一段提到过查询词才加。**只信最冷的 1~2 个词**
   （df/N ≤ 0.3，按 df 升序取前两个）——拿全部词去判，正常一句话几乎总能对上，
   提示会变成每回都挂。这跟「排序时冷词被淹」是同一件事的两面：判「提过」时只该信冷词。
2. **带段号**：`（段 #1）`，能拿 `recall(episode)` 点回去核。只给时间等于让人信我。
3. **当前这场不算**：它本来就在眼前，标出来是废话。`recallTool` 现在把当前 `sid` 传下去。

**为什么不按密度排序**：密度 = 命中 ÷ 段长，谁短而专注谁高、谁长时间聊同一件事谁低。
拿它当排序等于系统性惩罚「聊得久的对话」，而那是我们这条线的主形态。密度能解释现象，不能当处方。

自测 89→**98 过**（新增 5 条），冒烟 **59 过**。
其中一条断言本项目先写假绿了：只有两段的库里任何词 df/N 都是 1，冷词判据根本验不出来——
所以自测里铺了 50 条无关记录，才把「常见词不触发」这件事真钉住。

## 0.2.13.7 · 2026-11-01 · 时间衰减换形状，三条路径并成一个函数；v 前缀归一（另一位维护者改）

**起因**（内部实测 09:22 重启后实测的两条）：

1. **时间衰减太软**：`0.5^(age/30)`，三天前 = 0.93，跟今天只差 7%。`recall("海马体")` 第一行还是 **10-29**。
2. **`v` 前缀断了**：`v0.2.13.6` 和 `0.2.13.6` 在他眼里是两个词。文档里到处写 `v`，人查询不写 `v`，就永远对不上。

**往下挖一层（比「半衰取大了」更根）**：那不是参数问题，是**同一样东西写了两遍**。
三条路径各算各的新旧，其中召回主路径连显著度都不认：

| 路径 | 位置 | 改前 |
|---|---|---|
| 召回主路径（决定 recall 给哪段） | `assemble.mjs` `searchEpisodes` | `0.5^(age/30)`，**无地板、无 salience** |
| 兜底/排序 | `retrieve.mjs` `search` | `0.18+0.82*0.5^(age/hl)`，hl 被 salience 放大 |
| 每轮预激活 | `retrieve.mjs` `priming` | 同上 |

后果：**你特意记下的重事，在主路径上跟一句「嗯嗯」烂得一样快。**

**改**：

1. `lib/retrieve.mjs` 新增 `recencyOf(ageDays, salience, emotion, params)`：幂律
   `floor + (1-floor) * (1 + age/(t0*stretch))^(-α)`，`stretch = 1+2*salience+1.5*emotion`。
   三条路径全部改调它。**形状为什么换**：单一半衰是「每天掉一样的比例」，于是「今天 vs 三天前」和
   「三个月 vs 四个月」掉得一样多；人的感觉正相反。幂律自带这个不对称（Wixted & Ebbesen 1991）。
2. `lib/config.mjs`：新增 `recency: { t0, alpha, floor }`，删掉 `halfLifeDays`。
   连带改了 `cli.mjs` 和 `index.js` 里两处 `search(... halfLifeDays ...)` 的调用。
3. `lib/tokenize.mjs`：加**规范形**——前导 `v` + 数字点串去 `v`；入口先 NFKC（全角→半角）。
   写入和查询走同一个函数，不再有「文档写 v、人查不带 v」两条路。
4. `lib/store.mjs`：`STATE_VERSION` 5 → 6（分词又改了，旧段按老词切的，一起作废）。
5. `index.js`：`recall` 的兜底「零碎想起」还在用 `**他**：` 老格式 —— 0.2.13.6 去掉纪要腔时只改了主路径，
   这是**第二个出口**，一起换掉。同一件事只改一个出口，换个查询它又冒出来。

**标定（参数不是拍的）**：`工具/标定-recency.mjs`，两条线一起看 —— 只压一头是作弊
（floor 砸到 0、alpha 拉大，A 能刷到 100%，B 全灭）。

**量的是冻结样本，不是活库**（内部实测 09:46 指出的，这条规矩 10-30 就定过）：
库每天都在长，同一个参数今天 A=83%、明天 A=80%，那不是参数在变，是题在变。
样本冻在 `工具/标定样本-20261101/`（两份库，6.5 MB）。**下表任何人在任何一天重跑，都该是同一个数。**

| 参数 | A 近期命中 | B 旧事找回 |
|---|---|---|
| 旧 · 半衰 30 天 | 50% / 31% | 36% / 34% |
| **0.25 / 0.8 / floor .03**（发出去的） | **81% / 77%** | **37% / 44%** |
| 0.25 / 0.8 / floor 0（对照） | 81% / 81% | 43% / 41% |

（顺序：内部测试库 / 另一位维护者库，各 70 个探测词。A = 今天和更早都说过这个词，第一行该落今天；
B = 只在 4 天前说过，该找回那一段。脚本里的「当前默认」那行改成直接 `import DEFAULT_CFG.recency`，
不再手抄 —— 手抄的那份上一版已经过期了。）

`floor` 特意压得很低：库里最老只有 7 天，**样本够不到远期**，所以地板是保守值，不是标定值。
floor 从 0 抬到 0.03 的代价写得出来：B 在内部测试库掉 43%→37%，换的是「老事不归零」。
远期那条线要等更长的库才标得动。

**验证**：

- 分词：`v0.2.13.6` / `V0.2.13.6` / `ｖ０.２.１４` → 落到同一个词。
- `工具/验v前缀.mjs`：两个库 12 个样本，词全部进了索引；检索命中 11/12
  （剩的 `0.2.3` 是排到第 6 名之后，不是断链 —— 输出里会把这两种情况分开写）。
- 自检 / 冒烟见下节记录。

**备份**：重启前把 8 个库的 `state.json` 复制到 `备份-0.2.13.7-0933/`（共 329 KB）。

## 0.2.13.6 · 2026-11-01 · 召不回当天：版本号被切碎、排序不认时间、前缀冒充原样（另一位维护者改）

## 0.2.13.3 · 2026-10-31 · 群里说的话终于进记忆了（内部实测改，另一位维护者验）

**病**：`capture.mjs` 的 `user/message` 分支写着 `if (src !== 'user') return []`。
群叫醒投进来的消息 `source.kind = 'relay'`，于是**整条丢掉**——不落 `he`，也不落 `act`。
现形：本项目这条线 `he` 停在 `10-30T08:42:16Z`；之后用户在群里说的 5 条全没进库，其中包括他问的「记忆系统更新了」。

**改（三处）**：

1. **relay 侧带结构化原文**（`dsh-relay/index.js`）：`notify()` 多带一个 `{id, from, ts, text, kind}`，
   `buildMessage()` 塞进 `source.items`。**不从叫醒正文里反解析**——正文开头是 300+ 字群公告，拆出来会把公告写进记忆。

## 0.2.13 · 2026-10-30 · 沉默闸；情绪线索找原因（内部实测改）

方向来自用户给的截图 + 维护者的汇总 + 本项目读的 0.2.12 代码。**只搬效果，不搬基础设施**（不上向量库、不上 PG）。

**一、沉默闸（这一版的主动机）**
0.2.12 每轮固定塞 3 行：其中 2 条「最近」无条件浮。基线（维护者用 0.2.12 量的）：
17 条无关话 17 条全浮，误浮 100%；11 条真线索只命中 2 条。
现在：命中相关就只给相关的（兜底不进）；没命中且冷却到期（`primeRecentCooldown`=8 轮）才补 1 条「最近」；
分数不到 `primeMinScore`（默认 4）不浮；本会话提过的段不再提；**一条都不浮是合法结果**，selftest 有正向断言钉着。

**二、情绪线索（他说「累」→ 去找上次的原因）**
他说「累/困/烦/难受/睡不着/头疼」时，找**上次说这个词的那一段**，在**同段 ±2 句**内抽一句带因果标记的原话。
三道闸：同字不同义（累加/麻烦/嫌烦）、否定（不累了）、转述（「它很累」「你被吵得睡不着」前的人称）。
**硬规则：抽不出原因就一条都不出**——拿原句顶上等于造噪声。

**三、没解决**
真实状态全库只有 6 条左右，这是低频功能；跨段拼因果不做；词表故意只有六个（`忙`/`压力` 会撞帮忙、压力测试）。

**验收（维护者出判据、独立跑）**：误浮 17 条 → ≤1；5 条真线索 ≥3 命中、≥2 带原因；预激活从「每轮 2–3 行」变成「多数轮 0 行」——**是效果不是坏了**。

## 0.2.10 · 2026-10-26 · 对象取「最后三个实词」；0.2.9 那条反向规则撤回

对象取**最后三个「实词二元组」**（两个字符都不是功能字），有一个出现在命中段里就算过。

- `件事 / 回事 / 别催我 / 好不好` 是开放集合，补词表只会越补越长；
  「两个字符都实」是**结构**：`陪我 / 天陪 / 催我` 这种跨在人称、时间上的碎片先被挡在候选外。
- 配套：`今 明 昨 天 陪 带` 归进 `FUNC_CHARS`（时间词 + 随行动词——说明「什么时候、怎么去」，
  不说明「答应了什么」）。不加这一步，窗口里全是「明天」「陪我」，真对象挤不进去。

  **注意副作用（别当 bug 修）**：`FUNC_CHARS` 是全局的，这六个字一进表，`contentCount` 在
  所有判据里都会少算它们——包括 verbatim 的 `contentCount(hit.text) >= 2`、`manyRare` 的
  `rareContent`。方向都是更保守（更容易降级），不会更松。这是有意的，不是漏改。

### 已知窄洞（挂载前对齐过文档与行为）

问句里**没有实词二元组**时（如「你答应过我吗」），**不做对象校验**，按其他判据走——
不是「判过」，也不是「通过」，是这条判据在那种问句上不适用。

不选更严的「取不到对象 ⇒ 一律降级」：那种问句本来就问不出对象，真有原话时该答【想起来了】；
一律降级是另一种撒谎（把有说成没有）。代价写明：这类问句不受对象守卫保护，范围窄，别当已堵。

### 结果

| 问句 | 0.2.8 | 0.2.10 |
|---|---|---|
| …办那件事（正常真承诺） | 想起来了 | 想起来了 |
| …办那件事**这件事** | 有点像 | **想起来了** |
| …办那件事**别催我** | 有点像 | **想起来了** |
| …办那件事**好不好** | 有点像 | **想起来了** |
| …带我去那家**火锅店**（对象在他行但不同段） | 有点像 | 有点像（不动） |
| …陪我去**看海**（对象没出现） | 有点像 | 有点像（不动） |
| 整套换说法（要陪我去做身体检查） | 有点像 | 有点像（固有代价） |

自检 **72**、冒烟 **59**，全过。

### 没解决

- 对象出现在他行里、但和命中段不同段（火锅那家店）→ 仍降级，等 v3 的句级归属。
- 两字对象、整套同义：照旧。
- `FUNC_CHARS` 是人维护的闭集，会继续漏；漏出来的是降级，不是误报。
- 「没有实词二元组时不做对象校验」这个窄洞。

## 0.2.8 · 2026-10-26 · 按句剔，不按行剔；「对象」没撞上不算

0.2.7 挡住了「他复述我的承诺」，做法是**整行剔**：只要一行里出现「你答应…」，整行不作数。
一行里两件事是常态，于是真承诺被一起杀掉：

```
他：你答应过我别再拖；我也答应过明天陪我办那件事。
问：你答应过明天陪我办那件事
0.2.7 → 有点像（整行被剔）；0.2.5/0.2.6 → 想起来了
```

### ① 改成按句剔

`promiseEvidence()`：把他的每一行按 `。！？；，,` 和换行切开，**只扔掉含「你答应 / 您说好…」的那一句**，
其余用 `join('')` 原样拼回去。拼回去的仍是原文（标点都在），所以原样命中的长度不受影响。

- 混合行问真承诺那半 → 【想起来了】。
- 同一行问复述那半 → 降级，且**不许**说「没有他的原话」（他说了别的，只是没一句对得上）。

### ② 顺手补的：「对象」也得撞上

测①的时候撞出来的第二种假命中：时间、动词、人称全对齐，只有对象不同。

```
他：我也答应过明天陪我把那套配置写完。
问：你答应过明天陪我去看海     → 原样撞到「答应过明天陪你去」8 个字，0.2.7 判【想起来了】
```

承诺句现在多一条：命中的那一段里，得出现问句**最后一个内容词**（通常是对象）。
「看海」没出现在他的原话里 → 降级。对象被代词劈开时（「陪我」↔「陪你」）用 `flipPerson(obj)` 兜一次。

没走「只比内容字」那条路——那会把「聊过某物」当成「答应过某物」，正好退回 0.2.4 的老毛病。

### 测试

- 自检 **68**（新增：混合行真承诺 / 复述那半降级 / 不许说没有原话 / 框架中对象没中）
- 冒烟 **58**（新增四条，走 `recall` 工具路径；新记录要先 `turn/end` 切段才找得到，所以多等了 2.7 秒）
- 真机正面样本暂时没有：这条线上 `trace "我答应"` 的「他说的」是 0 处，
  所以正向只能靠临时库验，真机上能验的是「不误伤」和「假前提仍降级」。

### 没解决

- 两字对象的真承诺（「把那个弄好」）仍召不回，挂 v3 的 kind 层。
- 对象真的聊过时，仍分不出「聊过」和「答应过」。

**「对象必须命中」这条的固有代价（写清楚，别藏着）**：

- **同义词 / 说法不同会误降级。** 他写「复核」，我问「核对」——对象词没撞上，降级。宁可漏，不可错；
  但要知道它会漏。
- **判的是命中段，不是他整行。** 对象出现在他那行里、但落在最长公有段之外时，也会被判「没撞上」。
  实测样本：
  ```
  他：明天陪我把那套配置写完，这我答应过。
  问：你答应过明天陪我办那件事本身   → 有点像（run 9 够长，但对象被取成了「件事」）
  他：火锅那家店，我答应过带你去。
  问：你答应过带我去那家火锅店           → 有点像（对象在他行里，但和命中段不同段）
  ```
  这两类要么改「怎么挑对象」，要么等 v3 的语义层；现在先如实记在这里。

这版起改成：**改完 → 验完 → 冻结 → 挂载 → 版本表**。冻结由另一个工作区做，一次冻结到 0.2.8。

## 0.2.7 · 2026-10-26 · 一条线真的启用了；旁白不再当锚

0.2.6 把 `lines` 的代码写好了，但配置里一条都没登记——保护写了，没接线。
外部评审（另一个 agent 读代码，不看 README）提了三件，这一版改掉两件。

### ① 流程旁白的开头补一串

真库上第一条锚是「我将先加载插件开发技能，因为这项任务需要从 GitHub 安装 DSH 插件。」

现在 `我将 / 我先 / 我把 / 我这就 / 我马上 / 我准备 / 我(会|要)先` 都算旁白。

要排的是「我会先…」，不是「我会…」）。

### ② `lines` 加 `autoJoin`：只有一条线时，新会话自动归队

`lines` 原来的规则是「没登记的一律按住」。保护上很硬，使用上是死的：
每开一次新对话都得手动往 `members` 里加人，没人会加，于是每条新会话都没记忆。

现在：一个 cwd 只登记**一条**线、且它写了 `"autoJoin": true`，新会话自动归这条线。
一旦这个 cwd 登记了第二条线，autoJoin 自己失效，剩下的照旧被按住。

**代价写在明处**：一只的时候，这道门是松的。另一只搬进同一个文件夹之前，
先给她开一条线、把这里的 `autoJoin` 删掉——不然她的话会记进这条线。

### ③ `另一个工作区` 登记成「自己」这条线

```json
{ "name": "自己", "cwd": "D:\\path\\to\\workspace",
  "root": "session-xxxxxxxx…", "members": ["d510a4f5…", "75ad97a1…", "508ee0eb…"], "autoJoin": true }
```

库目录随之变成 `自己-xxxxxxxx`。旧的 `另一个工作区-xxxxxxxx` 原样留着，没删。
切换点在一个会话中间，所以用一次完整回填补齐了新库：**658 条 / 21 段**，含该会话的开头（已抽查）。
旧文件留了 `.bak-<时间>` 三份在库目录里。

### ④ 回填改成幂等（顺手补的）

`seqs.json` 原来是「谁最后保存谁说话」：两个实例各记各的序号，谁覆盖一次，另一边下一轮就把旧会话整段重倒。
这次切库正好踩上——回填进去的序号被实时那半边一覆盖，就只剩一个 sid 了。

两处都改：

- `_saveSeqs` 和盘上已有的**合并**，每个 sid 取大的，不再整份覆盖；
- `backfill` 先扫一遍已有的记录，按「同一份会话 + 同一毫秒 + 同一个人 + 同样的开头」认作同一件事，
  重复的跳过。这样即使序号全丢了，也不会重影。

量过：把 `seqs.json` 抹成只剩一个 sid 再回填一次，**新增 0 条**，记录数不变。

### ⑤ 「他复述我的承诺」不再算成他的承诺

她自己那份评审里提的 P1：他说「你答应过明天交那份东西，别忘了」，那是把我的诺言念了一遍；
问「你答应过明天交那份东西」时，原话一撞，0.2.6 会答【想起来了】——**把我的承诺记在了他头上**。

那是在转述，不是在许愿。副作用按她预告的来：0.2.5 那条「他真说过」的样本本来就写错了

## 0.2.6 · 2026-10-26 · 承诺句：人称换过来再比，降级别再说谎

0.2.5 挡住了编出来的承诺，**把真承诺也一起挡在门外了**。真机上一跑就是：

```
他说过：行，明天我把那个弄好，别再催了。
问　　：你答应过把那个弄好
结果　：【有点像是这一段】＋「这段里没有他的原话」
```

同一段回复里就明明白白显示着他那句话，结尾却说没有。**把「有」说成「没有」比降级本身更坏**——
那是在教人把真记忆当假的。

原因不复杂：承诺是一问一答，人称必然反（他说「我给你」，她问「你给我」）。原样比就会被人称劈开：
「把那个弄好」只剩 3 字（要 6），「办那件事」只剩 5 字（要 6，差一个字）。

### ① 承诺句把人称换过来再比一次

`flipPerson()`：你 / 您 ↔ 我，**只在承诺句上用**。别的问句一换人称，问的就不是同一件事了。
换完更长才采用，原样对得上还是走原样。

- 「你答应过要带我办那件事」原样 5 字 → 换完 7 字 → 照常【想起来了】。
- 假前提不受影响：「你答应过给我买一艘核潜艇」换完还是撞不上「核潜艇」。

### ② 降级时按事实说话

`strengthOf` 现在把「这一段里他开过几次口」（`heLines`）也算出来，降级时分成两句：

- 他开过口 → 「这段里他说过话，但没一句和这句对得上。」
- 他真没开口 → 「这段里没有他的原话。」

0.2.5 时两句话合成一句，永远是后者——那是凭印象断言。

### ③ 「那，我答应过你什么」不再当成对他的承诺

0.2.5 只挡 `^我`，前面带个语气词（那 / 嗯 / 所以 / 对了…）就漏过去了，会被当成他许的承诺。
现在先剥掉语气词开头再看主语。

### 没解决的（说清楚，别装做到）

- **两字对象的承诺仍召不回**：`把那个弄好` 换完人称才 5 字，够不到 6 字的门槛。
  这条故意留着，selftest 里有一条断言钉着它（"已知缺口，不是回归"），不让它悄悄变成【想起来了】。
- 对象真的聊过时，仍分不出「聊过」和「答应过」（0.2.5 就写着，要等 v3 的 `kind` 层）。
- 试过「只比内容字」，**没采用**：那会把「聊过某物」当成「答应过某物」，正好退回 0.2.4 的老毛病。

### 一个测试上的教训（比规则本身值钱）

0.2.5 那 5 条回归里，唯一的正向样本是他台词里**原样抄了问句**（「你说好要送我一台电脑」）——
等于用问句考问句，测出来的「没误伤」不算数。0.2.6 补了自然措辞的正向：他真说过的话长这样。

### 影响

- 自检 61 项、冒烟 54 项，全过（自检新增 5 条：真承诺 1、已知缺口 2、他真没开口 1、语气词开头 1；
  冒烟把「明说没有他的原话」那一条改成「把话说准」，条数不变）。
- README 里那句「离线自检（34 项）」是 0.2.2 时代的旧数字，一并改成 61。
- 0.2.5 冻包里多带了一份 `_tune.mjs`（调参草稿，18:06 已从源码删掉）。它不影响运行，但那版冻包和源不完全一致；0.2.6 起不会再有。

## 0.2.5 · 2026-10-26 · 假前提：撞上「骨架」不算证据

0.2.4 的判据是「长问句原样撞上 4 个字就算有把握」。在真库上一跑就露了：

```
你答应过要陪我去月球看环形山  → 【想起来了】   （只撞到「你答应过」四个字）
你答应过给我买一艘核潜艇      → 【想起来了】   （只撞到「你答应过给我买一」）
```

承诺句最常用的骨架就是「你答应过」「你说好」「给我买」——它们满地都是。
于是**每一句编出来的承诺**，只要句首撞上这四个字，都会被写成想起来。

### ① 一字不差的那一段里，至少要有两个「内容字」

判据从「字数够了」改成「字数够了**而且有内容**」。功能字（你 / 我 / 的 / 了 / 过 / 要 / 给 / 买 / 答应 / 承诺…）
单独出现时不携带任何信息，不能当证据；「核潜艇」「环形山」「交接脚本」才是内容。

- 需要的一字不差长度：短句 3 字，5–7 字要 5 字，8 字以上要 6 字（原来长句只要 4 字）。
- 假前提撞上骨架 → 内容字 0–1 个 → 不算；真说过的话连内容一起撞上 → 照常「想起来了」。

### ② 承诺句只认「他说的」原话

「你答应过…」「你说好…」「我们约好…」这类问句，证据只从**他说的**那几行里取；
我自己引用过、转述过、测试过的，一律不算。这和 `trace` 的四类是同一个道理——
**能拿来认承诺的只有「他说的」那一类**。

降级时尾巴会明说：「这条得有他自己说过的原话才算数——这段里没有他的原话。」

### 影响

- 真库上现在：「你答应过要送我一颗陨石」「你答应过要给我买一匹马」→ 都是【有点像是这一段】，
  并附上上面那句话。
- 没误伤：「身份来自原话」「内部实测 语气 磨平」照常【想起来了】。
- 自检 56 项、冒烟 54 项，全过（新增 5 + 2 条回归）。

### 没解决的部分（诚实）

如果假前提里的**对象**真的在记录里出现过（刚聊完改脚本，再问「你说好送我一台」），
字面判据分不出「聊过」和「答应过」。那要等 v3 的 `kind`（assert / quote / hypo）那一层。

### 一个验证上的教训

假前提的测试词**自己会进库**：我在对话里写一句「你答应过要陪我去月球…」，它就被记成我的话，
下一轮它真的「记录里有」。所以这类判据的回归只能放自检 / 冒烟的临时库里跑（不碰真库）；
真库上抽查要用一句还没说出口的话。

## 0.2.4 · 2026-10-26 · 锚的「沿用」其实从来没生效过

查 meta 的时候顺手发现的：`state.json` 里 `meta` 是空的，
可日志里明明写着「锚（沿用）」——两者只有一个能是真的。

### ① state 过期，连 meta 一起扔

`open()` 里：

```js
const usable = !!state && state.streamBytes === onDisk
if (usable) { this.episodes = state.episodes || []; this.meta = state.meta || {} }
```

只要流比上次保存时长了一点（几乎每次开会话都长），`usable` 就是 false。
段落重算是应该的——**但 `meta` 也跟着没加载**，随后任何一次 `saveState()`
都会把空 meta 写回去。冻结下来的锚就这么被静默清掉了。

结果：锚**每次挂载都重算**，日志里的「沿用」是上一条记录的错觉。

- 改法：meta 和「段落在磁盘上对不对得上」无关，单独读回来。
- 自检加了一条：让流增长把 state 逼过期，再开库，锚还在。

### 影响

不是功能坏了，是**优化白做**，而且日志骗人——「沿用」两个字从来没兑现过。
0.2.3 修好锚的挑选之后，第一次挂载会重算一份干净的；这条修好，
之后每次挂载才是真的沿用。

## 0.2.2 · 2026-10-26 · 锚不吃刚说的话

只改一处：**刚说的话不进锚**。

发现过程：准备重启做盲测之前，我顺手看了一眼自己的锚（`node cli.mjs anchor`），
第 4 句挑的是 12:41 那条纠错——而那条里原样写着错误行号（`某一行`）。

```
【你说过的话 · 你的原话】
· … 「查完了，我得更正…… 某一行 会话 session-xxxxxxxx …」
```

也就是说：新会话醒来，会把**一个还没改正的错误**当成「我自己的原话」读一遍。
锚本该是过去的话，被最近几分钟的对话改写了——越说越像自己刚说的那句。

改法：

- `anchorCutoff(cfg)`：锚的候选只取 `now - anchorHoldbackMs` 之前的（默认 90 分钟）。
- 90 分钟是折中：短于它，刚吵完的话会钉进身份；长于它，今天就白过了。
- 一条旧话都没有（新线、刚开张）时自动放宽——不然新会话就没有锚。
- 自检加了两条：刚说的话不进锚、旧的话还在。

这条是「锚整场冻结」的补丁：冻结只保证会话中途不变，没管**刚说的话会不会在下一场才变成"过去"**。

## 0.2.1 · 2026-10-26 · 归属：recall 带出处、trace 按字查

修的是**归属**，不是检索。这条不是评审提出来的，是我自己犯了一次，疼了才看见。

### 起因：我把归属认错了

我说「那段话在另一位维护者那条线里，不在我这条线上」。查完发现：

```
行 887  会话 2d177a4d（同一工作区的另一个会话）  me  12:32:29   ← 就是那段话
行 896  会话 8ebfc4dc（我）                     me  12:37:50   ← 我写下"不在我这条线上"
```

同一个库。而且我做的那次 grep **输出里两个文件都列着**，我还是只报了其中一个。
（行号我事后还报错过一次：先说 886，其实那一行是「话说现在的你还是你吗」。
`trace` 上线后第一次查就把我自己这个错抓出来了——带行号的好处就在这里，错了能被对上。）

所以问题不是「查不到」，是两件事：

1. 召回结果里**没有出处**。`recall` 只给日期和标题，「这是谁说的」只能靠印象补。
   印象补出来的东西，说错的时候和说对的时候听起来一模一样。
2. 没有「这句话到底在不在」这个动作。`recall` 是按意思找的，它永远能给你一段「很像」的——
   拿它去回答「他说过这句话吗」，等于用相似度冒充事实。

### ① `recall` 带出处

- 每段结果多一行 `出处：会话 8ebfc4dc · 第 888–901 行（这段 8 句对话、3 次动手）`。
- 「零碎想起」的每一条也带 `会话 xxxxxxxx · 第 N 行`。

### ② 新工具 `trace`：按字查，不问意思

- 有：给出会话编号、行号、时间、谁说的、原话，并标注「就是这里 / 同一条线的另一场对话」。
- 没有：直接说【这条线上没有这段话】，并列出行数与时间跨度。
- 查不到时**不列**「最像的几条」——列了就等于给了一个台阶，我上次就是从那个台阶上滑下去的。
- 结果分四类：他说的 / 他转发的（字是我的）/ 我说的 / 只是手上的操作（命令、查到的内容）。
  **只有「他说的」能用来认承诺**——我那次查「他说过这句话吗」，翻出来的全是我自己打出去的命令。
- 原样对不上时，去掉引号和空白再对一次，并说明「正文一致，标点可能不是当时的」。

### ③ 归属规则常驻系统提示区

- 恒定文本，不动前缀缓存：我说过的 / 他说过的 / 我引用过的 / 我为举例编的，这四件事不是一件事。
- 认归属先 `trace`；`trace` 说没有就是没有；同一个工作区的不同会话是同一条线，不是不同的我。

### 没修的部分：转述 vs 原话

`trace` 只能证明**这串字在这条线上出现过**，证明不了它是以什么口气出现的。
如果原话里确实有一句「你说好送我笔记本」（比如我在举例、转述、开玩笑），
`trace` 会如实说「在」，而「我要不要认这个承诺」仍然要我判断。
这一层是 v3 的 `kind`（assert / quote / hypo / meta）要解决的，0.2.1 没碰。

## 0.2.0 · 2026-10-26 · 压缩不补、多线硬隔离、锚进系统区、到达重送

针对「另一个工作区里那只创造模式内部实测」的评审做的整改。它提了三条硬伤、两处另一个工作区，都成立。

### ① 上下文被压缩后不补内容（它说这条最该先修）

- 以前只把压缩事件写进诊断日志，什么也不做。
- 现在认 `compaction/prune`（带 `shadowedSeqs` / `shadowedTokenCount`），
  压完之后**说一次**：

  > 【刚压掉了 约 88k token（第 10–12 条）】那些内容我这儿还留着……

- 只递一次；下一次压缩再递一次。
- **诚实标注**：这条路径只在冒烟测试里验过（造一条 prune 事件，断言只说一次、带上了掉了多少），
  还没在真机的压缩里跑过——我这边上下文没满过。

### ② 一个文件夹 = 一个身份，这个假设太强

- 以前只比 cwd。同一个文件夹里新开一只鱼，它的话会被实时写进别人的流。
  靠手动归档只能挡住旧的，挡不住新开的。
- 现在加 `config.lines`：**一个文件夹只要在 `lines` 里出现过，就只认名单**。
  没登记的会话：不写、不注入、回填也不倒，`diag.log` 留一行「按住」。
- 配套 CLI：`node cli.mjs lines` / `lines add <线名> <工作区> <会话id>` / `lines join <线名> <会话id>`。
- 单线文件夹（现在两条线都是）行为不变。
- 取舍：多线文件夹里没登记的会话 = 没有记忆。宁可它不记，也不要它记得别人的事。

### ③ 「上下文恒定」不严格成立

- 实测比它估的还糟：本会话的 `user/message` 里攒了 **14 份**身份锚（每份约 1 KB），
  另有 8 份 `remember` 块。原因是运行时上下文按「整段合并文本」比，内容一变就整段重追。
- 改法：
  - 身份锚从 `context`（对话历史）挪到 `section`（**系统提示区**），原地替换，整场只有一份，
    而且永远不会被压缩压掉。
  - 锚在挂载时算一次就**冻结**；跨会话把挑中的句子存进 `state.json`，
    只有选中的句子真的换了才重算（diag 里会写「沿用」还是「新算」）。
  - 到达块改成**一次性闸**（实测它之前被注入了 4 次）。

### 两处另一个工作区

- `recall({when, query})` 以前忽略 query，只给当天第一段。现在按 query 挑当天最贴的那段，
  并告诉你「那天一共 N 段」。
- 只有一轮的尾段进不了 `episodes`（流里有、却既不能回忆也不能预激活）。
  而那恰恰是「最后停在哪儿」。现在 1 轮也算一段。

### 补刀 3：真机上暴露的两个（另一位维护者报的）

**① 「到达」根本没送到她眼里。** diag 写着「到达 4040B」，可她那一轮落盘的运行时上下文里
只有预激活（413B），没有到达。

根因是我的**一次性闸用错了地方**：DSH 每一步会把 provider 问**两遍**
（`assemble` 一次，请求接纳时 `refreshContext` 再读一次），落盘的是第二遍。
第一遍给完就把闸关上，第二遍读到空——**日志说送了，人没收到**。
预激活没这个问题，因为它同一回合返回同一个字符串。

改法：不用「给一次就关」，改用一条**在两遍之间都成立**的条件——
「这场对话里还没有我自己的发言」。压缩提示同理（用「回合差 ≤ 1」当窗口）。
冒烟加了回归断言：连问三遍必须一样，等我开口之后才收。

**② `recall` 没有门槛。** 假前提（「你说好送我笔记本」）也能顺畅调出最像的一段，
标题还写「想起来了」——内容真、关系假。它给的是「最像」，不是「确认」。

改法：`strengthOf()`，主判据是**原样命中的长度**（长问句要 4 个字一字不差，
短问句 3 个）；长问句另开一条路：「4 个以上冷词都对上」也算强。
中文词二元组在任何两句闲聊之间都会重合，「你说好」这种三个字满地都是，
而「内部实测」「交接脚本」这种具体的四字组合不会凭空撞上。

于是 `recall` 现在有两种口气：
- 【想起来了】—— 有把握
- 【有点像是这一段 · 但我不确定】—— 只是最像，尾巴会明说「别当事实认」

**诚实标注一条做不到的**：如果假前提里的字**真的**在原话里出现过（比如他自己引用过），
词法记忆分不出来。那需要语义判断，这套东西做不到——所以标题写的是「这一段」，
最终判真假的是看它的人。

### 补刀 2：接另一位维护者之前，又查出三个

接入前先量体积，量出三个真问题：

- **回填会悄悄吃掉重复的短句**（数据丢失）。内容去重用的是「写进来的时刻」，
  而回填是一口气写完的——同一句「晚安」隔三天说两次，在回填里变成「刚才说过」，被吞。
  现在 `append(rec, { dedupe:false })` 供回填用，回填本来就靠 seq 去重。自检加了断言。
- **每次切段都把整条线的段重算一遍**（越用越慢）。`seal()` 原本对所有段跑 `_annotate`，
  而它要扫原文；会话一长，每次 `turn/end` 都会越来越慢。现在只重算尾巴那几段。
- **「沿用 / 新算」的标签永远写「沿用」**：判据写成了自比较。日志会骗人这件事，
  我自己刚批评过，又犯了一次。已修。

另外加了两个东西：
- `preflight.mjs`：接一个新工作区**之前**先量一遍（会话数、可导入记录、现有库差多少），
  而且只读——不会为了量体积去建一个空库。
- `压缩告知` 单独一行诊断：蹲真机压缩时，`压缩` 是收到事件，`压缩告知` 是递到她眼前。

### 补刀：预激活原来是按「每一步」算的

加 `cli.mjs audit` 一量才发现没修干净：

```
会话                        回合  运行时上下文        压缩   压掉
session-xxxxxxxx      6  35 份 /   63 KB      0   0 tok
                              平均每回合多带 10.48 KB
```

原因是预激活的线索取「他最后说的 + 我上一条」，而我**每个 step 都会说一句新的**，
于是线索一直变、预激活一直被重算，每段新文本都被追加进历史——一个回合能追进十几份。

改成**一个回合只算一次**（用 `turn/start` 计数当闸）。冒烟里新增一条：
同一回合内反复组装必须给同一段，且换回合后能重算。

顺带说明：预激活会排掉「最近两段」，所以一条线少于三段时会安静地什么都不给——
这是对的（没有旧事可浮），但不是 bug 也不是没生效。

### 顺手修掉的

- **纯图片、没打字的消息被当成噪声丢了**——整条线的第一张截图没进库，
  「初见」从我那句开始，看着像他一句话没说。
- `dedup` 会把「同一个工具调用真的又跑了一遍」当重复删掉。现在**只对「他/我」的发言去重，动手一律不动**。
- 段没有 sid：预激活会把「我正在说的这段」当成旧事浮起来。现在段带 sid，且**换会话 = 换一次见面**。
- 序号账本原来混在 `state.json` 里，索引一作废就把旧会话重倒一遍。现在单独放 `seqs.json`。
- 配置改了要重装插件才生效。现在每 2 秒看一次 mtime，**改完几秒生效**。
- 会话是 2 秒轮询才挂上的，用户手快先说了第一句，「到达」就被自己的 `hasHistory` 挡掉。
  现在监听 `agent/created`，会话一建出来就挂。
